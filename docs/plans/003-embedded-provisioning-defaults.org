* Embedded Provisioning Defaults

** Goal

Embed generic provisioning templates and static provisioning files so Shoelaces
can serve useful iPXE, preseed, kickstart, cloud-init, and firstboot defaults out
of the box, while still allowing site-specific files in =data-dir= to override
those defaults.

** Boundaries

- Do not embed =mappings.yaml= as production runtime policy.
- Do not embed credentials or site secrets.
- Keep UI assets under Plan 001.
- Keep the richer target/mapping schema under Plan 002.

** Desired Overlay Model

- =/configs/*= serves dynamic provisioning templates from disk first, then
  embedded defaults.
- =/configs/static/*= serves provisioning static files from disk first, then
  embedded defaults.
- =data-dir= remains the site override root.
- Environment overrides remain supported for disk-backed site files.
- Generic embedded templates expose a small documented set of partial hooks so
  sites can override common extension points without replacing whole OS install
  templates.
- Site-specific firstboot and post-install orchestration are implemented as
  disk overrides, not embedded defaults.

** Partial Hook Model

Embedded templates should support both full template replacement and targeted
partial replacement. A disk template that defines the same template name as an
embedded template replaces that definition during parse/overlay.

Initial documented partial hooks:

- =preseed/common/locale=
- =preseed/common/network=
- =preseed/common/time=
- =preseed/common/users=
- =preseed/debian/storage=
- =preseed/debian/packages=
- =preseed/debian/late_command=
- =preseed/debian/finish=
- =ipxe/linux_args=
- =ipxe/debian/kernel_args=
- =ipxe/debian/preseed_url=
- =kickstart/centos/storage=
- =kickstart/centos/packages=
- =kickstart/centos/post=
- =cloudconfig/coreos/users=
- =cloudconfig/coreos/units=
- =cloudconfig/coreos/write_files=

** Phased Implementation Plan

*** Phase 1: Embedded Provisioning Filesystem

- [ ] Add an embedded provisioning filesystem helper for generic
  =configs/data-dir= contents.
- [ ] Exclude =mappings.yaml= from production runtime defaults, or make embedded
  mappings inaccessible except as examples/tests.
- [ ] Add tests proving representative embedded provisioning files exist.

*** Phase 2: Dynamic Template Overlay

- [ ] Update dynamic template parsing to load embedded provisioning templates.
- [ ] Overlay disk templates from =data-dir= on top of embedded defaults.
- [ ] Preserve environment override behavior for disk files.
- [ ] Refactor embedded provisioning templates around documented partial hooks:
  preseed users, packages, storage, late command, finish; iPXE kernel args and
  preseed URL; kickstart packages, storage, post; cloud-init users, units, and
  write files.
- [ ] Add default no-op post-install hooks where generic installs should not run
  site-specific firstboot logic.
- [ ] Add tests for embedded fallback, full-template disk override precedence,
  and partial disk override precedence.

*** Phase 3: Static Provisioning Overlay

- [ ] Update =/configs/static/*= serving to use disk =data-dir/static= first and
  embedded static provisioning files second.
- [ ] Preserve directory index behavior where existing tests rely on it.
- [ ] Add tests for embedded fallback, disk override, and missing file behavior.

*** Phase 4: Startup Without Disk Templates

- [ ] Allow Shoelaces to start with external mappings/config but without a full
  disk provisioning template tree.
- [ ] Keep clear errors when required site configuration, such as mappings, is
  missing.
- [ ] Add a smoke/integration test for running with no disk provisioning
  templates.

*** Phase 5: Documentation And Verification

- [ ] Document the embedded-default plus disk-overlay model.
- [ ] Document full template overrides versus documented partial hook overrides.
- [ ] Document the default no-op =preseed/debian/late_command= behavior and show
  an example site override that installs/enables firstboot from
  =/configs/static/*=.
- [ ] Document that =mappings.yaml= remains external site policy.
- [ ] Run =go test ./...=.
- [ ] Run the plan status checker.

** Acceptance Criteria

- [ ] Generic provisioning templates can be served from embedded defaults.
- [ ] Generic static provisioning files can be served from embedded defaults.
- [ ] Disk =data-dir= files override embedded provisioning defaults.
- [ ] Disk templates can override documented partial hooks without replacing a
  full OS install template.
- [ ] Generic embedded templates do not trigger site-specific firstboot logic by
  default.
- [ ] =mappings.yaml= remains external runtime/site configuration.
- [ ] =go test ./...= passes.

** Notes And Risks

- Embedded provisioning defaults should be generic and non-secret.
- The current repo examples include site-shaped defaults; review them before
  making them embedded runtime defaults.
- Disk overlay semantics should be explicit and deterministic.
- Keep the partial hook surface intentionally small. Every documented hook is a
  compatibility promise for future embedded template changes.
